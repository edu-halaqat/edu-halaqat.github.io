# أفق الخطط: نتيجة التنفيذ 2026-10-21

تم تثبيت النسخة المصححة في Supabase وتفعيلها على طالب واحد فقط بعد الاختبار. لا تعني هذه النتيجة تعميم التنظيف على جميع الطلاب.

## النتيجة المثبتة
- PostgreSQL 17: نجحت اختبارات ست توليفات من اتجاه الحفظ والمناهج المتدرجة والمراجعة الخطية/تقسيمات المصحف، إضافة إلى النطاق والجدولة والصلاحيات.
- نسخة محلية معزولة من خطط طالب: أعيد توليد 813 صفًا دون اختلاف في الآيات والمقادير والدورات والمقاطع والعناوين.
- التشغيل التجريبي الحي نجح ثم تراجع عن التغييرات.
- التفعيل الفعلي: 1099 صفًا قبل العملية، 286 بعدها، وإزالة 813 صفًا مستقبليًا فقط.
- تحققت العملية داخل معاملة من بقاء الحصائل والحضور دون تغيير. الدالة نفسها تتحقق من مطابقة الصفوف المحتفظ بها بالكامل.
- نجح تشغيل تابع التجديد بعد التفعيل؛ لم يحذف أو يضف صفوفًا عند التكرار.
- مهمة cron مفعلة عند الدقيقة 17 من كل ساعة؛ تعالج خمسة طلاب مستحقين كحد أقصى، ويعاد فحص كل طالب بعد يوم. عدد المسجلين حاليًا: واحد.
- الأفق 120 يومًا، وعتبة التجديد 60 يومًا. بيانات تاريخ الختم المتوقع لا تُختصر إلى الأفق.

## حدود النتيجة
الانخفاض في عدد الصفوف لا يثبت انخفاض حجم القرص الفيزيائي؛ لم يُنفذ VACUUM FULL. لم يُقَس بعد أثر التشغيل على سعة الحسابات اليومية، ولم تُنقل أي بيانات طالب إلى GitHub. إنشاء الخطط الحالي لم يُعدَّل، لذا يظل تقليل التوليد الأولي وتوسيع التسجيل مرحلتين لاحقتين.

فحص الأمان أظهر للجدول الخاص ملاحظة معلوماتية بأن RLS مفعّل بلا سياسات؛ هذا مقصود لأن الجدول إداري غير مكشوف وأذونات anon/authenticated مسحوبة. لم تُمنح صلاحيات مستخدمين لمعالجة هذه الملاحظة.
مرجع الملاحظة: https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy

## المراقبة
```sql
select enabled, next_check_at, last_checked_at, last_result
from private.plan_horizon_targets
order by next_check_at;
select jobname, schedule, active
from cron.job where jobname='sanabil-plan-horizon-refill';
```

إيقاف الجدولة بعد قص الأيام يتطلب خطة لتعويض الأيام قبل انتهاء الأفق المتبقي؛ لا توقف التجديد وتترك الخطط المقصوصة دون متابعة.

## GitHub وبيانات الخطط
GitHub مناسب للمراجع والقواعد المشتركة غير المرتبطة بالطلاب. مستودع المنصة عام، فلا تنشر فيه خططًا شخصية أو حصائل أو معرّفات الطلاب. نقل سجلات متغيرة باستمرار إلى Git يزيد تاريخ المستودع ولا يوفر صلاحيات الصفوف التي توفرها Supabase.

التصميم المستهدف: قواعد مشتركة بإصدار واضح، إعدادات خطة الطالب وتقدمه وتعديلاته في قاعدة البيانات، أيام مستقبلية محدودة قابلة لإعادة التوليد، ونسخة محلية مؤقتة للعرض والعمل دون اتصال. هذه توصية معمارية؛ نقل المراجع للواجهة ليس جزءًا منفذًا من هذا التغيير.
