# قياس سنابل الوحي من السعودية واختبار التزامن

## 1. المقارنة العادلة من شبكة الجوال السعودي

أداة المتصفح `network-benchmark.html` تقيس سرعة المسار الحالي فقط. لا تستطيع JavaScript داخل المتصفح إجبار الاتصال بالعنوان الأصلي مع إبقاء SNI وشهادة `snabilalwahy.com`.

للمقارنة المباشرة من **هاتف Android نفسه**، استخدم تطبيق Termux الموثوق (من F-Droid) واتصاله الحالي؛ لا يحتاج الحساب أو كلمات مرور أو الوصول إلى بيانات الطلاب.

داخل Termux:

```sh
pkg update
pkg install python curl
curl -fsSL https://raw.githubusercontent.com/edu-halaqat/edu-halaqat.github.io/main/tests/sa-origin-paired.py -o sa-origin-paired.py
python sa-origin-paired.py
```

تُجري الأداة 600 مقارنة مزدوجة (1,200 GET عامًا) للملفات المنشورة عبر Cloudflare مباشرة وبالاتصال بـ GitHub Pages الأصلي عبر `curl --resolve snabilalwahy.com:443:185.199.108.153`. يظل اسم الموقع وشهادة HTTPS كما هما. تنوع الأداة ترتيب المسارين، والصفحات والملفات الكبيرة والصغيرة والطلبات الجديدة والمتكررة، وتحفظ `sa-compare-summary.json` و`sa-compare-pairs.csv` على الجهاز.

- **تنبيه:** الاختبار قد يستهلك عشرات الميغابايت من بيانات الجوال؛ استخدم اتصالًا يسمح بذلك.
- يستلزم 500 مقارنة صحيحة على الأقل للحكم. عند ظهور أخطاء HTTP أو انقطاع الشبكة لا تدّعِ نجاحًا كاملًا.
- يوفر اتصال جهاز واحد نتيجة تخص تلك الشبكة واللحظة؛ يُفضّل تكرار القياس بشبكة ثانية.
- `--resolve` لا يغير DNS أو Cloudflare. الاختبار قراءة عامة فقط.
- نتائج المقارنة ليست اختبارًا لتسجيل الدخول أو سعة Supabase.

## 2. اختبار الضغط: بيئة Supabase تجريبية فقط

المشروع **الإنتاجي المحظور للاختبارات المكثفة**: `fvzoogbdezueswyihxiz`.

عند توفير مشروع Staging مستقل وبيانات طلاب ومعلم تجريبية فيه، يمكن تشغيل `tests/sanabil-staging-load.js` عبر k6. يرفض البرنامج التشغيل على عنوان الإنتاج، ولا يعمل دون `I_CONFIRM_STAGING_ONLY=yes`. المراحل: 10 ثم 25 ثم 50 ثم 100 مستخدم افتراضي، مع قياس P95 ومعدل فشل الطلبات. العمليات الحالية **قراءات مصادق عليها** للحلقات والطلاب والمقررات وليست حفظ حصائل.

```sh
I_CONFIRM_STAGING_ONLY=yes \
STAGING_SUPABASE_URL=https://STAGING_PROJECT.supabase.co \
STAGING_ANON_KEY=STAGING_PUBLISHABLE_KEY \
STAGING_TEACHER_JWT=TEST_TEACHER_ACCESS_TOKEN \
STAGING_CIRCLE_ID=STAGING_CIRCLE_ID \
k6 run tests/sanabil-staging-load.js
```

يجب عدم مشاركة رموز الوصول هنا أو وضعها في GitHub. يُنشأ حساب معلم تجريبي ونُسخ بيانات اصطناعية مسبقًا. تجرى الكتابة وحفظ الحصائل فقط في Staging بعد تجهيز بيانات وتوقعات السجلات وطريقة تنظيفها.

**معايير هندسية أولية:** P95 دون ثانيتين ومعدل أخطاء أقل من 0.5%؛ هذه أهداف وليست نتائج مثبتة. لا تتحول إلى سعة إنتاجية معتمدة قبل مقارنة اختبارات RLS، الحفظ، التزامن وقياس CPU/اتصالات PostgreSQL.

## 3. قياس أثر التحميل المحلي الجديد

قارن المقياس الآتي قبل وبعد تحديث الخدمة على الجهاز نفسه:
- تسجيل أول فتح للواجهة بعد إغلاق المتصفح بالكامل، ثم الفتح الثاني والثالث.
- وجود النسخة `sanabil-shell-20261022-v36-mobile-versioned-cache` في Service Worker عند اكتمال التحديث.
- إرسال `X-Sanabil-Benchmark: 1` فقط من أداة قياس الشبكة لتجاوز تخزين عامل الخدمة، حتى لا تختلط سرعة Cache Storage بسرعة Cloudflare.
- فتح صفحة المعلم، ثم صفحة الحصيلة والتأكد من تحديثات الخطط وحفظها. قياس زمن ظهور البطاقات وعمليات الحفظ الفعلية من لوحة الأداء، وليس الاكتفاء بـPageSpeed.
