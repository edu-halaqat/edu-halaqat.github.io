# سنابل المباشر — خطة نشر خادم فيديو خاص داخل السعودية

**حالة الملف:** مخطط تجهيز (لا يشغّل الفيديو ولا يضيف طلابًا أو يبث بياناتهم وحده).

## البنية المعتمدة
- واجهة الحلقات والبوابة: https://snabilalwahy.com — GitHub Pages (منفصلة عن الوسائط).
- نطاق القاعة الثابتة بعد بناء المسار: https://snabilalwahy.com/class/<opaque-room-id>
- خادم LiveKit/ WebRTC داخل السعودية: `wss://video.snabilalwahy.com`.
- خادم TURN/TLS داخل السعودية: `turn.snabilalwahy.com`؛ لا توجّه الوسائط إلى عقد خارج المملكة.
- بوابة JWT/إدارة القاعات: على خادم خاص داخل السعودية، خلف HTTPS؛ تبقى أسرار LiveKit هناك حصريًا.
- قاعدة سنابل الحالية Supabase (ap-southeast-1، سنغافورة): **لا تعتبر بيانات الطلاب كلها موطنة بالسعودية**. استضافة البث فقط سعودية في هذه المرحلة.

## متطلبات الخادم السعودي
- خادم VPS/VM أو خوادم خاصة مع موقع مركز بيانات سعودي موثق، IP عام ثابت، صلاحية SSH، وإمكانية ضبط الجدار الناري.
- DNS: سجل A للنطاق video وسجل A للنطاق turn إلى عنوان الخادم السعودي.
- شهادات TLS صالحة للنطاقات وأتمتة تجديدها؛ HTTPS/WSS إلزامي للكاميرا والميكروفون.
- اعتماد [مولّد LiveKit الرسمي](https://docs.livekit.io/transport/self-hosting/vm/) لضبط Docker Compose وCaddy وRedis وLiveKit، وعدم استخدام مفتاح devkey في الإنتاج.
- المنافذ المبدئية وفق دليل LiveKit: HTTPS/TURN 443 TCP، 80 TCP لإصدار شهادة، 7881 TCP بديل WebRTC، 3478 UDP، و50000–60000 UDP لوسائط WebRTC. يمكن اختيار UDP mux وفق سعة البث والسياسات. لا تفتح Redis 6379 ولا API 7880 للعامة.
- مراقبة الموارد والاتصالات والنسخ الاحتياطية للتهيئة والمفاتيح (لا تُسجل مكالمات أو مقاطع صوتية افتراضيًا).
- سجلات الأداء لا تتضمن تسجيل صوت الطالب أو فيديوه؛ توثيق سياسة الاحتفاظ ببيانات الحضور/المدة فقط.
- مفاتيح LiveKit من مدير أسرار الخادم السعودي حصريًا. لا تضعها في GitHub أو جافاسكربت الموقع أو Supabase العامة.

## المسار التعليمي الآمن (للتنفيذ بعد توفير الخادم)
1. المشرف يختار نمط التعليم: `in_person | remote | hybrid` **بحقل مستقل عن نوع الحلقة** (حفظ/تلقين/إجازة).
2. إنشاء معرّف قاعة عشوائي ثابت للحلقة، لا يحمل اسم الطالب أو رقم هاتفه أو هويته.
3. المعلم المسند يبدأ لقاء جديدًا من حسابه؛ الخادم يتحقق من إسناده في سنابل ثم ينشئ جلسة قصيرة العمر.
4. الطالب يدخل عبر هوية طالب موثقة أو رمز دعوة قصير الصلاحية مقيد بطالب وحلقة. رابط القاعة وحده ليس تصريحًا بالانضمام.
5. طلبات الطلاب تظهر في قائمة الانتظار؛ لا تصدر JWT LiveKit إلا بعد موافقة المعلم (expiry قصير وربط هوية الطالب بالغرفة).
6. فصل `admitted` (مسموح له في الحلقة) عن `reciting` (يتلو حاليًا). الميكروفون مغلق لبقية الطلاب، والطالب الحالي فقط ينشر الصوت بعد الإذن.
7. تبقى الحصيلة داخل `save_daily_outcomes_guarded` في سنابل؛ لا تنشئ مصدر حصائل موازيًا أو ترحيلًا مكررًا.
8. نهاية اللقاء تلغي جلسة الانضمام الجديدة وتطلب طرد الموجودين من غرفة LiveKit. دعم استئناف اللقاء بقرار المعلم.
9. تسجيل اللقاءات معطل، ولا يُفعّل إلا بسياسة مستقلة وموافقة صريحة مناسبة للقاصرين.

## حدود أمنية مهمة
- خادم GitHub Pages لا يستطيع توليد JWT بأسرار لأنه واجهة عامة. الخادم السعودي يجب أن يوقع التصاريح.
- `guardian_access` الحالي ليس بحد ذاته هوية طالب مخوّل بالصوت والصورة. بناء مصادقة الطالب خطوة إلزامية قبل فتح القاعة للعامة.
- لا تقبل أسماء مدخلة من زائر مجهول باعتبارها إثبات انتماء للحلقة. التحقق من الطالب وإسناده شرط قبل إدخاله.
- الإشراف التربوي والحصائل والتقارير لا تعتمد مجرد «دخل الرابط» بوصفه حاضرًا أو مسمّعًا.
- يجب اختبار iOS Safari وAndroid Chrome وWindows وMac والتابلت وضعف الشبكة وتبديل الصوت قبل الإنتاج.

## مراحل التحقق قبل إطلاق البث
1. تجهيز بيئة خادم اختبار سعودي منفصلة مع عنوانه وشهادة TLS واختبار `wss://video.snabilalwahy.com`.
2. فحص اختبار حي لمعلم وطالبين من حسابات تجريبية فقط: انتظار، قبول/رفض، صوت وكاميرا، تسميع، إنهاء.
3. إثبات حفظ الحصائل في السجلات نفسها لا في تخزين الفيديو. لا تبدأ ببث طلاب حقيقيين.
4. اختبار الحمل لعدد الحلقات المتزامنة المطلوب وقياس bandwidth/CPU والكمون مع شبكات سعودية متعددة.
5. تدقيق خصوصية الصغار وسياسة البيانات وتحديد موقع وسائط الصوت والصورة ونسخ السجلات.
6. إعلان الإطلاق فقط بعد نجاح الاختبارات والاستضافة الفعلية داخل السعودية.

**متطلب لم يُقدّم بعد:** حساب لدى مزود VPS سعودي مع صلاحيات لإدارة VM وDNS. لا يوجد خادم فيديو حي قبل توفير هذه العناصر.
